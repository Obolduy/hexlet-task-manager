# Спека 002 — фронтенд демо-монорепы (apps/web)

Минимальный экран со списком задач поверх `apps/api` из [`001-backend.md`](001-backend.md).
Реализуется до эфира. Фильтрация по исполнителю и статусу в эту версию не
входит — это отдельная задача, которая ставится на самом эфире поверх
готового экрана.

## 1. Границы

Входит: `apps/web` — один экран со списком задач, чтение `GET /tasks` и
`GET /users`, компонентная разбивка, типы ответов API, два компонентных
теста.

Не входит: фильтрация по исполнителю/статусу, роутер, стор (Pinia/Vuex),
UI-библиотеки, любые мутации (создание задачи, смена статуса из интерфейса),
бэкенд, CI, review-action. Команды запуска и тестирования, требования к PR —
в `AGENTS.md`, здесь не дублируются.

## 2. Структура apps/web

```
apps/web/
  src/
    main.ts               # монтирование приложения
    App.vue                # корень: обёртка страницы, рендерит TaskScreen
    components/
      TaskScreen.vue        # загрузка данных, состояния загрузки/ошибки/пусто
      TaskList.vue           # список задач
      TaskListItem.vue        # одна задача
      StatusBadge.vue          # статус задачи
    api/
      types.ts               # Task, User, TaskStatus
      tasks.ts                 # fetchTasks()
      users.ts                  # fetchUsers()
  tests/
    TaskList.spec.ts
    StatusBadge.spec.ts
```

Слои: `components/` не делает запросов напрямую, кроме `TaskScreen.vue` —
единственного места, которое вызывает `api/`. `api/` не импортирует ничего
из `components/`.

## 3. Контракт данных и типизация

Источник правды — `apps/api/src/schemas.py` (`TaskOut`, `UserOut`,
`TaskStatus`). Отдельного OpenAPI-клиента и генерации типов нет — оба
приложения лежат в одном репозитории, поэтому типы в `api/types.ts`
пишутся вручную и синхронизируются глазами при изменении `schemas.py`. Это
тот же принцип, что и с `AGENTS.md`: агент читает контракт файлом по
соседству, а не через отдельный слой генерации.

Соответствие полей:

| `schemas.py` (Pydantic)          | `api/types.ts` (TS)                                   |
|-----------------------------------|--------------------------------------------------------|
| `TaskStatus` (Enum)                | `type TaskStatus = "new" \| "in_progress" \| "in_review" \| "done"` |
| `TaskOut.id: int`                    | `id: number`                                            |
| `TaskOut.title: str`                  | `title: string`                                          |
| `TaskOut.description: str \| None`     | `description: string \| null`                             |
| `TaskOut.status: TaskStatus`            | `status: TaskStatus`                                       |
| `TaskOut.assignee_id: int \| None`       | `assigneeId: number \| null`                                 |
| `TaskOut.created_at / updated_at: str`    | `createdAt: string` / `updatedAt: string`                      |
| `UserOut.id: int`                          | `id: number`                                                     |
| `UserOut.name: str`                          | `name: string`                                                     |
| `UserOut.email: str`                           | `email: string`                                                      |

`assignee_id`/`created_at`/`updated_at` переводятся в camelCase на границе
`api/tasks.ts` (тонкий маппинг снейк→кэмел сразу после `fetch`, до попадания
данных в компоненты) — дальше по приложению snake_case не используется.

## 4. Компоненты

- **`App.vue`** — корневой компонент. Только рендерит `<TaskScreen />` и
  задаёт минимальную обёртку страницы (заголовок, контейнер). Данных не
  хранит.
- **`TaskScreen.vue`** — владелец состояния экрана: по `onMounted` вызывает
  `fetchTasks()` и `fetchUsers()`, хранит `tasks`, `users`, `isLoading`,
  `error`. Строит `assigneeNameById: Record<number, string>` из `users`
  (`computed`). Рендерит состояние загрузки, состояние ошибки или
  `<TaskList>` с готовыми данными.
- **`TaskList.vue`** — принимает `tasks: Task[]` и `assigneeNameById:
  Record<number, string>`. Если `tasks.length === 0` — рендерит текст
  «Задач нет». Иначе рендерит `TaskListItem` на каждую задачу.
- **`TaskListItem.vue`** — принимает `task: Task` и `assigneeName: string |
  null`. Рендерит заголовок, описание (если есть), исполнителя (или
  «Без исполнителя», если `assigneeName === null`) и `<StatusBadge>`.
- **`StatusBadge.vue`** — принимает `status: TaskStatus`. Чистое
  презентационное отображение значения статуса в читаемый текст на
  русском (`new` → «Новая», `in_progress` → «В работе», `in_review` → «На
  проверке», `done` → «Готово»). Без запросов, без событий.

Поток данных однонаправленный, сверху вниз через props; событий наверх
компоненты не эмитят — в этой версии экран только читает данные.

## 5. Состояния экрана

`TaskScreen.vue` — единственное место, где эти состояния обрабатываются:

- **Загрузка** — пока не пришёл ответ хотя бы на один из двух запросов:
  текст «Загрузка…» вместо списка.
- **Ошибка** — если `fetchTasks()` или `fetchUsers()` упал (сеть, не-2xx
  статус): текст с сообщением об ошибке вместо списка, без ретраев.
- **Пусто** — запросы успешны, `tasks` — пустой массив: обрабатывается
  внутри `TaskList.vue` (см. раздел 4), а не в `TaskScreen.vue`.

## 6. Тесты

Vitest + `@vue/test-utils`. Два теста:

- **`TaskList.spec.ts`** — на массиве из нескольких задач рендерится ровно
  столько `TaskListItem`, сколько элементов в массиве; на пустом массиве
  рендерится текст «Задач нет» и ни одного `TaskListItem`.
- **`StatusBadge.spec.ts`** — параметризованный тест: для каждого значения
  `TaskStatus` компонент рендерит ожидаемый русский текст.

## 7. apps/web/AGENTS.md — состав

Файл дополняет корневой `AGENTS.md`, действует только внутри `apps/web`.
Должен содержать:

- **Стек**: Vue 3 + Vite + TypeScript, только Composition API и
  `<script setup>` — никаких Options API компонентов.
- **Запреты**: без роутера, без стора (Pinia/Vuex/любой другой), без
  UI-библиотек и CSS-фреймворков. Стилизация — минимальный CSS, без
  дизайн-системы.
- **Зависимости**: новые зависимости в `package.json` не добавлять без
  явного указания в задаче (`vitest` и `@vue/test-utils` — уже
  зафиксированное исключение из этой спеки, дальше действует общее
  правило).
- **Типы**: источник правды для форм данных — `apps/api/src/schemas.py`,
  не выдумывать поля, которых там нет; при добавлении поля в `schemas.py`
  вручную обновлять `apps/web/src/api/types.ts`.
- **Слои**: только `TaskScreen.vue` обращается к `api/`; остальные
  компоненты — чистые от side-effects, получают данные через props.
- **Тесты**: `vitest`, у компонента с логикой (не чисто вёрстка) —
  минимум один тест.
- **Размер**: файл компонента не должен разрастаться — если `.vue`-файл
  переваливает за ~80 строк, это повод разбить его на два компонента, а
  не правило добавлять компоненты заранее.
