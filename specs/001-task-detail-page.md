# 001 — Страница деталей задачи

Источник: issue #19 «Открывать детали задачи на отдельной странице».
Сейчас информация о задаче видна только в карточке в общем списке. Нужно,
чтобы по клику на задачу открывался отдельный экран с её полной
информацией, доступный по прямой ссылке (чтобы можно было поделиться URL
на конкретную задачу).

## Объём

Входит: отдельный URL на конкретную задачу с прямой ссылкой, переход туда
по клику из списка без перезагрузки страницы, отображение полной
информации о задаче, состояния загрузки/ошибки/«задача не найдена»,
переход назад к списку.

Не входит:
- редактирование или удаление задачи с экрана деталей — issue просит
  только просмотр;
- `vue-router` или любая другая библиотека роутинга — фронтенд намеренно
  маленький, два экрана не оправдывают отдельную зависимость;
- хлебные крошки, анимации переходов, история/предыдущая-следующая задача;
- пагинация, фильтры, произвольные несуществующие пути (см. ниже, как они
  обрабатываются) — не относятся к этой задаче.

## Бэкенд (`apps/api`)

Изменения не требуются. `GET /tasks/{task_id}` уже существует
(`routes/tasks.py`), реализован через `task_service.get_task` →
`models/task.py`, отдаёт `TaskOut`, при отсутствии задачи —
`404 {"detail": "task not found"}`. Уже покрыт тестами
(`tests/test_tasks.py::test_get_task_success`,
`::test_get_task_not_found`). Контракт ответа не меняется.

## Фронтенд (`apps/web`)

### Зависимости

Новые зависимости не добавляются. Вместо `vue-router` — свой минимальный
модуль на полтора десятка строк поверх `history.pushState` +
`popstate`, этого достаточно для двух статичных путей. `nginx.conf` уже
настроен на `try_files $uri $uri/ /index.html`, поэтому открытие
`/tasks/7` напрямую (например, по внешней ссылке) будет работать без
изменений в инфраструктуре — сервер всегда отдаёт `index.html`, а какой
экран показать, дальше решает JS на клиенте.

### Навигация: `src/router.ts` (новый)

Один файл, без роутера-библиотеки:

```ts
export type Route = { name: 'list' } | { name: 'task-detail'; id: number }
```

- `parseLocation(): Route` — разбирает `window.location.pathname` по
  regexp `^/tasks/(\d+)$`; совпало → `{ name: 'task-detail', id }`; не
  совпало (включая `/`, `/tasks/abc`, любой другой путь) → `{ name: 'list' }`.
  Осознанное упрощение: неизвестный путь тихо показывает список, а не
  страницу 404 — отдельная 404-страница не входит в объём задачи.
- `currentRoute` — `ref<Route>(parseLocation())`, реактивный источник
  текущего экрана для `App.vue`.
- `navigate(path: string): void` — `history.pushState(null, '', path)` +
  пересчитывает `currentRoute`.
- слушатель `popstate` на `window` — синхронизирует `currentRoute` при
  навигации назад/вперёд браузером.
- `onLinkClick(event: MouseEvent, path: string): void` — общий обработчик
  для всех внутренних ссылок: если клик обычный (левая кнопка, без
  Ctrl/Cmd/Shift/Alt), делает `preventDefault()` и `navigate(path)`;
  иначе не трогает событие — открытие в новой вкладке через Ctrl/Cmd+клик
  и переход правой кнопкой мыши продолжают работать как обычная ссылка.

### Слои

- `src/App.vue` — рендерит `TaskScreen` или `TaskDetailScreen` по
  `currentRoute.value.name` (`v-if`/`v-else`), во втором случае
  прокидывает `id` пропом. Заголовок `<h1>Задачи</h1>` переезжает внутрь
  `TaskScreen.vue` — у страницы деталей будет собственный заголовок
  (название задачи), а не общий на всё приложение.
- `src/api/tasks.ts` — новая функция `fetchTask(id: number): Promise<Task>`,
  дергает `GET /tasks/{id}`, использует существующий `mapTask`. 404
  отличается от прочих ошибок (проверка `response.status === 404`), чтобы
  экран деталей мог показать именно «задача не найдена», а не общий текст
  ошибки.
- `src/components/TaskListItem.vue` — заголовок задачи оборачивается в
  `<a :href="`/tasks/${task.id}`" @click="onLinkClick($event, ...)">` —
  обычная ссылка, работает с клавиатуры без дополнительной разметки, и
  как настоящий URL (виден в статус-баре, копируется через «копировать
  адрес ссылки»).
- `src/components/TaskDetailScreen.vue` (новый) — как и `TaskScreen.vue`,
  сам обращается к API; получает `id: number` пропом от `App.vue`.
  Остальные компоненты (`TaskList`, `TaskListItem`, `StatusBadge`)
  остаются презентационными, без side-effects, данные только через
  props — это не меняется.

Поскольку при переходе список ↔ детали `App.vue` полностью пересоздаёт
дочерний компонент (`v-if`/`v-else`, а не один компонент с меняющимся
пропом), `TaskDetailScreen.vue` грузит данные один раз в `onMounted` — не
нужен `watch` на изменение `id`, экран каждый раз монтируется заново с
нужным значением.

### Контракт `TaskDetailScreen.vue`

Props: `{ id: number }`.

При монтировании параллельно вызывает `fetchTask(id)` и `fetchUsers()`.
Состояния:
- загрузка — текст `Загрузка…` (как в `TaskScreen.vue`);
- задача не найдена (404) — `Задача не найдена` + ссылка `Назад к списку`
  (через `onLinkClick`);
- прочая ошибка — текст ошибки + ссылка `Назад к списку`;
- успех — заголовок с названием задачи, `StatusBadge`, описание (или
  `Без описания`), исполнитель (или `Без исполнителя`), даты создания и
  обновления, ссылка `Назад к списку`.

Имя исполнителя резолвится так же, как сейчас в `TaskScreen.vue` — через
`Record<number, string>`, собранный из списка пользователей.

Компонент дублирует загрузку пользователей (`fetchUsers()`) отдельно от
`TaskScreen.vue` — в приложении нет общего стора или кеша, поэтому при
переходе на страницу деталей список пользователей запрашивается заново.
Для текущего размера приложения это осознанно принятое упрощение —
заводить стор ради одного повторного запроса было бы избыточным
усложнением, тем более в задаче, которая явно просит не усложнять
фронтенд.

Даты (`created_at` / `updated_at`) выводятся как есть, в исходном
ISO-виде из ответа API — в проекте нет утилиты форматирования дат,
добавлять её ради одной страницы не входит в объём этой задачи.

### Тесты (`apps/web/tests`)

- `router.spec.ts` (новый) — `parseLocation` для `/`, `/tasks/42`,
  `/tasks/abc` и произвольного пути; `navigate` обновляет
  `window.location.pathname` и `currentRoute`; `onLinkClick` вызывает
  `preventDefault`+`navigate` на обычном клике и не трогает событие при
  Ctrl/Cmd/Shift/Alt или не-левой кнопке.
- `TaskDetailScreen.spec.ts` (новый) — мокается `fetch`:
  - состояние загрузки рендерится до ответа;
  - успешный ответ — рендерятся название, статус, описание, исполнитель,
    даты;
  - 404 — рендерится `Задача не найдена`;
  - сетевая/прочая ошибка — рендерится текст ошибки.
- `TaskListItem.spec.ts` (новый, минимально) — ссылка на задачу указывает
  на правильный `href` (`/tasks/{id}`), клик по ней вызывает `onLinkClick`
  (можно проверить через мок модуля `router.ts`).
- `TaskList.spec.ts` — без изменений: `TaskListItem` теперь рендерит
  обычный `<a>`, а не компонент стороннего роутера, так что существующее
  монтирование без дополнительного контекста продолжает работать.

## Отступления и границы

Все решения в этой спеке принимались только на основании кода в текущей
ветке (`issue-19-no-agents-with-spec`), текста issue #19 и явных указаний
автора задачи в переписке — в частности, решения не добавлять
`vue-router` и сохранять фронтенд намеренно маленьким. Файлы вида
`AGENTS.md`, спеки или коммиты, присутствующие в других ветках или в
истории репозитория, но отсутствующие в рабочей копии текущей ветки, не
учитывались как источник ограничений.
