# Спека 003 — дата создания задачи по-человечески (issue #17)

Каждая карточка задачи в списке показывает, когда задача создана, в
относительном формате («2 часа назад», «вчера», «3 дня назад») вместо
сырого ISO из `created_at`.

## 1. Границы

Входит: `apps/web` — утилита форматирования относительного времени,
её использование в `TaskListItem.vue`, тесты.

Не входит: `updated_at` (см. раздел 3.1 — решение показывать только дату
создания), бэкенд (данные уже есть в `TaskOut`/`Task`, схему не менять),
автообновление текста с течением времени без перезагрузки страницы (см.
раздел 3.4), сортировка/фильтрация задач по дате.

## 2. Структура apps/web

```
apps/web/
  src/
    utils/
      relativeTime.ts       # formatRelativeTime(iso, now?) — чистая функция
    components/
      TaskListItem.vue        # + строка с относительной датой создания
  tests/
    relativeTime.spec.ts     # тесты чистой функции форматирования
    TaskListItem.spec.ts      # тест, что карточка рендерит эту строку
```

`utils/` — новая директория, никаких side-effects и обращений к `api/`, как
и у остальных не-`TaskScreen` частей приложения. `relativeTime.ts` не
экспортирует ничего, кроме `formatRelativeTime`.

## 3. Контракт и решения по формату

Данные не меняются: `Task.createdAt` (см. `apps/web/src/api/types.ts`) уже
приходит строкой ISO 8601 с таймзоной (из `apps/api/src/models/task.py`,
`_now()`). Новый код — только форматирование на фронтенде.

### 3.1 Что показывать

Показывается только **дата создания** (`createdAt`), не `updatedAt`.
Название issue («Показывать дату создания задачи по-человечески») говорит
именно про создание; `updatedAt` для карточки в списке — отдельная задача,
если понадобится.

### 3.2 Функция `formatRelativeTime`

```ts
function formatRelativeTime(iso: string, now: Date = new Date()): string
```

Второй аргумент — точка отсчёта, по умолчанию `new Date()`; передаётся
явно в тестах, чтобы не мокать глобальное время.

Границы интервалов (считаются от разницы `now - date` в секундах,
округление вниз):

| Разница                       | Текст                                   |
|--------------------------------|-------------------------------------------|
| < 60 сек                        | «только что»                                |
| < 60 мин                          | «N минуту/минуты/минут назад»                 |
| < 24 ч                              | «N час/часа/часов назад»                        |
| ровно 1 день (24–48 ч)                | «вчера»                                           |
| 2–6 дней                                | «N дня/дней назад»                                  |
| ≥ 7 дней                                  | абсолютная дата `DD.MM.YYYY`                          |

Число дней/часов/минут считается как целочисленное деление разницы, не по
календарным суткам — «вчера» здесь означает «24–48 часов назад», а не
«предыдущий календарный день». Это осознанное упрощение (без учёта
локальной полуночи), чтобы не тянуть в проект библиотеку дат — при
необходимости календарной точности потребуется отдельная задача.

Русские окончания (минута/минуты/минут, час/часа/часов, день/дня/дней)
считаются одной вспомогательной функцией `pluralize(n, one, few, many)` по
стандартному правилу склонения (n % 10 и n % 100), внутри
`relativeTime.ts`, не экспортируется.

Абсолютная дата (`≥ 7 дней`) форматируется вручную как `DD.MM.YYYY` в
локальной таймзоне браузера — без `Intl.DateTimeFormat`, чтобы не зависеть
от локали окружения (в частности, в тестах).

Отрицательная разница (дата создания в будущем — рассинхронизация часов
клиента и сервера) трактуется как «только что»; специального сообщения об
ошибке нет.

### 3.3 Отображение в `TaskListItem.vue`

Новая строка `<p class="task-item__created">` после исполнителя, со
значением `formatRelativeTime(task.createdAt)` через `computed`. Полный
атрибут `title="{{ task.createdAt }}"` на этом элементе — чтобы точное
время оставалось доступным по наведению, без отдельного компонента.

### 3.4 Что сознательно не делается

Строка не обновляется сама по себе с течением времени (например, «2 минуты
назад» не станет «3 минуты назад» без перезагрузки/повторного маунта
компонента). Живое обновление потребовало бы таймера в компоненте, что
issue не требует и что усложнило бы тестирование; при необходимости —
отдельная задача.

## 4. Тесты

- **`relativeTime.spec.ts`** — параметризованные случаи на фиксированном
  `now`: «только что» (0 и 30 сек), минуты (1, 2, 5, 21 — разные окончания),
  часы (1, 2, 5 — разные окончания), «вчера» (24 и 47 часов), дни (2, 6 —
  разные окончания), абсолютная дата (7 и 30 дней — проверка формата
  `DD.MM.YYYY`), отрицательная разница (дата в будущем → «только что»).
- **`TaskListItem.spec.ts`** — монтирование с фиксированным `task.createdAt`
  и системным временем (`vi.setSystemTime`), проверка, что в тексте карточки
  есть ожидаемая относительная строка и что атрибут `title` элемента с
  датой равен исходному `createdAt`.

## 5. Отступления от общих правил

Нет отступлений — новый код укладывается в существующие слои и запреты
(`apps/api/AGENTS.md`, `apps/web/AGENTS.md`), новых зависимостей не
добавляется.
